# Плитки головної ведуть до потрібного блоку, «Назад/Вперед» відновлюють позицію

- **Task id:** home-tile-anchors
- **Services:** web (frontend)
- **Infra changes:** no
- **QA:** e2e (Playwright), глибина `smoke`

## 1. Goal
Відвідувач клікає плитку на головній (наприклад, «FieldQuote») і одразу бачить відповідний блок на сторінці Work/About, а не її початок. Коли він натискає «Назад» (чи «Вперед») у браузері, сторінка показується там, де він її залишив, а не з початку.

## 2. Service changes

### web (frontend)

**Поточний стан (для довідки):** плитки на `/` ведуть на `/work` і `/about` без якоря; [src/hooks/usePageTransition.ts](../../src/hooks/usePageTransition.ts) після кожної зміни `pathname` (крім REPLACE) прокручує вікно на початок, зокрема і при POP. Хедер `position: sticky`, висота ~68 px (64 px на вузьких). На `<html>` є `scroll-behavior: smooth` (вимикається при reduced motion).

**1. Якорі на сторінці Work** ([src/pages/WorkPage.tsx](../../src/pages/WorkPage.tsx)) — кожна група (`data-testid="work-group"`) отримує `id`:
| Група | `id` |
|---|---|
| SkyService POS (кейси) | `work-sky` |
| Mobile apps (картка FieldQuote + NDA) | `work-apps` |
| My projects (AI Chat) | `work-own` |

На сторінці About id уже є: `ai` (`section-ai`) і `stack` (`section-stack`). Їх не змінювати.

**2. Посилання плиток головної** ([src/pages/HomePage.tsx](../../src/pages/HomePage.tsx)):
| Плитка (`data-testid`) | Куди веде (`href`) |
|---|---|
| 1-ша `home-work-tile` (POS-термінал) | `/work#work-sky` |
| 2-га `home-work-tile` (FieldQuote) | `/work#work-apps` |
| 3-тя `home-work-tile` (AI Chat) | `/work#work-own` |
| `home-ai-tile` (Як я будую) | `/about#ai` |
| `home-stack-tile` (Стек) | `/about#stack` |
| `view-work` (Переглянути роботи) | `/work` — без змін |
| `home-link-contacts` (Усі контакти) | `/contact` — без змін |
Якорі задавати константами в коді (не в словнику), щоб вони були однакові для всіх мов. Зіставлення плиток робіт із якорями — за порядком у `workTiles` (його не змінювати).

**3. Прокрутка при переході на сторінку (PUSH, клік по посиланню)** — переробити `usePageTransition` (чи додати поруч окремий хук; на вибір розробника):
- Адреса з hash, і елемент з таким `id` є на сторінці → після рендеру сторінка **одразу** (без анімації, `behavior: 'instant'`) стоїть так, що верх блоку видно під sticky-хедером (блок не захований під хедером; відступ досягається через `scroll-margin-top` на якорях або через розрахунок зміщення).
- Адреса без hash, або елемента немає → як зараз: на початок сторінки.
- Фокус: як зараз, на `<main>` з `preventScroll: true` (щоб фокус не збивав прокрутку).
- Прямий захід за адресою з якорем (вставили `/work#work-apps` в адресний рядок / оновили сторінку) → теж показується блок.
- skip-link (`#main`) і REPLACE-навігація працюють як раніше.

**4. Відновлення позиції при «Назад» / «Вперед» (POP) на всіх сторінках:**
- Перед тим як піти зі сторінки (будь-яка навігація роутера), зберігати поточний `scrollY` для **цього запису історії** (ключ — `location.key`). Сховище — `sessionStorage` з обгорткою `try/catch` (якщо недоступне — у памʼяті модуля); так позиції переживають і перезавантаження вкладки.
- При POP → прокрутити **одразу** (без анімації) на збережену позицію цього запису. Якщо сторінка ще недостатньо висока (контент/зображення догружаються), повторювати спробу на наступних кадрах, поки висоти не стане достатньо, максимум ~1 с; потім лишити як є.
- Немає збереженої позиції для запису → якщо є hash з наявним елементом — до блоку, інакше на початок.
- `history.scrollRestoration = 'manual'`, щоб браузер не конкурував із роутером.
- Фокус при POP теж на `<main>` з `preventScroll: true`.

**5. Чого не змінювати:** вигляд плиток, тексти, хедер, бургер-меню, логіку `RouteLink` (без дублів запису при повторному кліку), анімації появи `reveal`. Якщо `reveal`-елементи з'являються лише при потраплянні у видиму область, після стрибка до блоку вони мають показатися (не лишатися прозорими).

**Required `data-testid`:** нових немає. Тестувальник використовує наявні: `home-work-tile` (3 шт., по порядку), `home-ai-tile`, `home-stack-tile`, `view-work`, `home-link-contacts`, `page-work`, `page-about`, `page-home`, `work-group` (3 шт., з id `work-sky` / `work-apps` / `work-own`), `section-ai`, `section-stack`, `apps-card`.

**Тести (юніт):** оновити/додати тести хука прокрутки та `href` плиток.

## 5. Acceptance criteria
1. AC-1: На `/` плитки мають `href`: POS → `/work#work-sky`, FieldQuote → `/work#work-apps`, AI Chat → `/work#work-own`, «Як я будую» → `/about#ai`, «Стек» → `/about#stack`; `view-work` → `/work`, `home-link-contacts` → `/contact`.
2. AC-2: Клік по кожній із 5 плиток відкриває потрібну сторінку, і верх цільового блоку видно у вікні, не під хедером (верх блоку ≥ нижньої межі хедера і в межах верхньої половини вікна, якщо сторінка достатньо довга нижче блоку).
3. AC-3: Прямий захід на `/work#work-apps` (і `/about#stack`) показує відповідний блок.
4. AC-4: `view-work` і пункти меню ведуть на початок сторінки (`scrollY` = 0), як раніше.
5. AC-5: Прокрутити `/` вниз (напр. до плиток робіт), клікнути плитку → «Назад» у браузері: `/` показується на тій самій позиції (± 5 px), а не з початку.
6. AC-6: Після AC-5 «Вперед» повертає на Work на позицію, де сторінку залишили (± 5 px).
7. AC-7: Те саме для інших сторінок: прокрутити `/about` вниз → перейти через меню на `/contact` → «Назад» → `/about` на збереженій позиції.
8. AC-8: Блок після переходу за якорем видимий (не прозорий через анімацію появи); на вузькому екрані (мобільна ширина, бургер-меню) AC-2 і AC-5 теж виконуються.

## 6. Test focus (for QA)
- **What changed for the user:** куди саме відкриваються Work/About після кліку по плитках головної; позиція прокрутки після «Назад/Вперед».
- **What could break nearby:** перехід через меню/лого (має бути з початку), skip-link, редірект невідомих шляхів на `/`, бургер-меню (scroll lock), подвійний клік по посиланню на поточну сторінку.
- **Not to re-test:** тексти, теми, мови, CV-кнопки, вигляд карток.
- **Risky cases:** блок захований під sticky-хедером; «Назад» спочатку показує верх, а потім стрибає; коротка сторінка не може прокрутитися так, щоб блок був зверху (тоді досить, щоб блок був видимий); вузькі ширини (Mobile apps на телефоні довгий).
- **Tight screens:** 375, 768, 1440 px ширини.
